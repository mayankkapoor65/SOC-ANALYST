# v1.0.1 Patch Report

**Release:** v1.0.1 (Final Patch)  
**Date:** 2026-08-13  
**Scope:** Targeted bug fixes from Final Release Audit — no API changes, no new features, no dashboard changes

## Summary

This patch addresses two medium-severity findings from the final release audit:

1. Threat intelligence feed parsing could crash on non-numeric `threat_score` values.
2. Account Takeover correlation fired for new users without an established baseline.

Both fixes are internal service-layer changes only. All existing API contracts and dashboard behavior are unchanged.

## Bugs Fixed

### 1. Threat Intelligence — Non-numeric `threat_score` Handling

**Before:** `_normalize_ioc()` called `int(entry.get("threat_score", 0))` directly. Values like `"bad"` raised `ValueError`, which could crash feed loading and downstream API calls.

**After:**
- `_safe_threat_score()` parses numeric values safely and defaults invalid input to `0`
- A warning is logged: `Invalid threat_score 'bad' for IOC 1.2.3.4; defaulting to 0`
- `_safe_confidence()` added as a defensive companion to prevent similar crashes on malformed confidence values
- JSON and CSV feed paths both use safe parsing
- API endpoints (`GET /threat-intel`, `GET /threat-intel/ip/{ip}`) no longer crash on malformed feed data

### 2. Correlation Engine — Account Takeover Baseline Logic

**Before:** `check_account_takeover()` called `_is_new_device(device, typical)` where `typical` was `None` for users without baselines. `_is_new_device()` returned `True` for any device when no baseline existed, causing first-time users to match the "new device" step of the attack chain.

**After:** `check_account_takeover()` returns early (`None`) when `_get_user_baseline()` finds no baseline record. Device deviation is only evaluated for users with an established `typical_device`.

**Preserved behavior:** Users with baselines still trigger Account Takeover when the full chain (new device → high risk → privileged access) is detected.
